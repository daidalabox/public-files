第1章 業者の側から見た裏側

ここからは、筆者がシステムの業者の側で、案件を受ける立場として働いていた経験から書く章です。発注する側にいると見えにくい、業者の考え方と費用の中身をまとめます。

業者を疑うための章ではありません。業者の事情を知ると、業者も発注する側も、無駄なリスクと費用を負わずに済む頼み方ができるようになります。

# 見積もりの中身は、おおよそ3つに分かれる

まず、見積もりの全体像です。パッケージ製品を導入する案件(製品をほとんど、またはまったく作り込まない場合)では、筆者の経験上、見積もりの金額は、おおよそ次の3つが3分の1ずつになることが多いです。

  • 業者の利益と販売の経費(含まれるもの:業者の利益、営業や管理にかかる費用)
  • 機器・製品の費用(含まれるもの:サーバー、パソコン、ネットワークの機器、製品の使用料など)
  • 案件を進める費用(含まれるもの:設定、データの移し替え、テスト、教育、打ち合わせなどの人の作業)

ただし、これは筆者の感覚値で、幅はかなり大きいことに注意してください。業者、製品、案件の規模によって大きく変わりますし、作り込みが多い開発の案件では、案件を進める費用の割合がずっと大きくなります。それでも、この目安を知っていると、パッケージ製品の見積もりを見たときに「どこが膨らんでいるか」の当たりが付けられます。

例えば、機器の費用が全体の半分を超えているなら、機器の選び方や台数を見直す余地があるかもしれません。案件を進める費用が極端に小さいなら、作業の一部が見積もりから漏れている可能性があります。

# 見積もりの読み方:どこに余裕が乗りやすいか

# 相見積もりを取り、明細を細かく出してもらう

比較できる案件では、原則として複数の業者から同じ条件で見積もりを取ります。製品や契約の都合で1社しか選べない場合は、作業内容や過去の契約などで妥当性を確かめます。そのうえで、明細をできるだけ細かく出してもらうように頼みます。「一式」の明細では、比べようがないからです。

頼み方の例です。

比較のため、明細は工程ごとに分け、さらに「機器・製品」と「作業」に分けて出していただけますか。作業は、工程ごとに人数と日数が分かる形でお願いします。

# 明細は「工程ごと」に、「物」と「工数」に分ける

明細は、次の2つの軸で分けてもらいます。

  • 工程ごと:要件の確認、設計、設定、データの移し替え、テスト、教育、本番の立ち上げ、立ち上げ後の支援など
  • 物と工数:機器・製品(物)と、人の作業(工数)

この形にそろえると、業者ごとの見積もりを、同じ表に並べて比べられます。付録の「見積もりの比較表」の見出しは、この形で作っています。

# 物は、一番安いところを引き合いに出す

同じ型番・ライセンス構成・保証条件であれば、機器や製品の価格は比較しやすい項目です。ただし、保守・初期設定・納入条件の違いも価格差に含まれるため、条件をそろえて比較します。

比較表で一番安い業者の価格を引き合いに出し、「この機器は、他社ではこの価格でした。合わせていただけますか」と交渉します。物の価格は、交渉の余地が一番分かりやすい場所です。

# 工数は、具体的な場面でイメージできるまで聞く

作業の工数は、業者ごとに大きく違うことがあります。差があるところは、なぜ違うのか、納得できるまで聞きます。

聞き方の例です。

  • 「この『設定 10人日』は、具体的にどんな作業ですか。画面の数や、設定の項目の数で教えてください」
  • 「他社はデータの移し替えが3人日、御社は10人日です。何が違いますか」
  • 「教育は、何回・何人に・何時間の想定ですか」

具体的に答えられる業者は、作業の中身をきちんと見積もっています。答えがあいまいな業者は、余裕を多めに乗せているか、中身を十分に見ていない可能性があります。

# 安すぎる見積もりに要注意

逆に、ほかより極端に安い見積もりにも注意が必要です。最初の見積もりを安く見せて、後から追加の費用を請求してくる、または必要な作業が漏れていて、導入の途中で問題になる、ということがあります。

安すぎる見積もりは、後の追加費用や漏れの元になり、トラブルの種になります。 安い理由を必ず確かめ、「この見積もりに含まれていないものは何ですか」と聞いてください。

# 良い業者を見分ける、筆者の感覚

最後に、筆者の経験からの感覚です。見積もりを出すのが早く、最初から明細が細かい業者は、良い業者である確率が高いです。

見積もりが早いのは、似た案件の経験が多く、作業の中身がすぐにイメージできるからです。明細が最初から細かいのは、作業を積み上げて見積もっているからです。逆に、見積もりが遅く、「一式」ばかりの業者は、中身を詰め切れていないことがあります。

# 連携の費用が高くなる理由と、交渉の仕方

# 受け取る側の連携は、なぜ高いのか

システム同士をつなぐ費用は、見積もりの中でも特に高くなりやすい項目です。理由は、データを受け取る側の作業が重いからです。

データを受け取る側の業者から見ると、次のような事情があります。

  • 相手のシステムは他社の製品で、どんなデータが来るか、事前に正確には分からない
  • 想定外のデータ(空欄、桁の違い、文字の違いなど)が来たときの処理を、作り込む必要がある
  • 受け取ったデータが、自社のシステムのどこに影響するかを確認し、影響範囲に応じてテストする必要がある

つまり、受け取る側は、既存機能への影響も考えた検証が必要になることになります。そのため、費用が高くなるのです。

# 出す側の費用も、作業の中身で変わる

データを出す側が既存機能を使って決まった形式のデータを書き出すだけなら、作業費は比較的小さく済む場合があります。一方、新たな抽出ロジックや変換、認証、既存機能の改修が必要なら、送信側にも相応の工数が発生します。

見積もりで、出す側の連携の費用が大きい場合は、中身を確かめてください。「出す側として、具体的にどんな作業が必要ですか」と聞きます。

# 交渉の仕方

連携の費用を抑えるには、受け取る側の不確かさを減らすことです。

  1. 出す側のデータの仕様を、先に渡す:項目の名前、桁数、文字の種類、空欄になる場合の扱いなどを、出す側の業者から受け取り、受け取る側に渡す
  2. 見本のデータを渡す:実際の形式のデータ(中身は架空のもの)を渡すと、受け取る側が作業を正確に見積もれる
  3. 受け取る側の形式に、出す側を合わせてもらう:受け取る側が普段使っている形式がある場合、出す側にその形式で出してもらうと、受け取る側の作り込みが減る
  4. 連携の範囲を絞る:最初からすべてのデータをつなぐのではなく、本当に必要な項目だけにする

不確かさが減れば、受け取る側の業者は、リスクのための上乗せを減らせます。仕様と見本のデータを先に渡すだけで、連携の見積もりが下がることは珍しくありません。

# 業者が本当に欲しい依頼書の書き方

# 業者は、工程をイメージできる材料を探している

業者が見積もりを作るとき、一番知りたいのは、どんな工程が、どれくらい必要になるかです。依頼書の中身から、要件の確認、設計、設定、テスト、教育などの工程を一つ一つ思い浮かべて、作業量を見積もります。

工程をイメージできる材料が少ないと、業者は「分からない部分」を見積もりに含めるしかありません。

# 担当者が分かっていないと、リスクとして上乗せされる

ここが大事なところです。依頼書があいまいで、担当者がシステムのことをあまり分かっていないと判断されると、見積もりは高くなりやすくなります。

これは、業者がぼったくろうとしているからではありません。「この案件は、要件が途中で変わりそう」「確認に時間がかかりそう」というリスクを見込んで、上乗せしているのです。業者にとっても、後で赤字になるのは避けたいからです。

# 要件のレベルまで棚卸しされていると、安く出やすい

逆に、業務の棚卸しが要件のレベルまで終わっていて、依頼書の具体性が高いと、見積もりは安く出やすくなります。業者が見込むリスクが小さくなるからです。

具体性の高い依頼書とは、次のようなものです。

  • あいまい:「受注を管理したい」

→ 具体的:取引先は約〇〇社、注文は月に約〇〇件、受け方はFAX・メール・Webの3種類。受注から出荷・請求までを1つの流れで扱いたい

  • あいまい:「在庫とつなぎたい」

→ 具体的:出荷の実績(項目の一覧は別紙)を、1日1回、決まった形式のファイルで在庫のシステムに渡す

  • あいまい:「使いやすくしたい」

→ 具体的:注文の受け付けから請求までの今の手順(別紙)のうち、手での転記を3か所なくしたい

  • あいまい:「教育もお願いしたい」

→ 具体的:管理者〇人、リーダー〇人、全社員〇人。管理者とリーダーは対面2回、全社員は資料と動画

①と②の手順で作る、システム台帳、データの流れ図、業務フロー、要件の一覧は、そのまま依頼書の材料になります。手順を丁寧に進めることは、見積もりの不確実性を減らすことにつながるのです。

# 保守契約の落とし穴

# 機器が絡むときは、実際に使う年数で計算する

機器が絡む契約は、実際に使う年数で総額を計算します。例えば、7年使う予定なら、7年分の保守の費用を含めて比べます。

  • 機器の費用(A社:安い、B社:高い)
  • 年間の保守の費用(A社:高い、B社:安い)
  • 7年間の総額(A社:逆転して高くなることがある、B社:逆転して安くなることがある)

機器が安くても、7年の総額で見ると逆転することがあります。初期の費用だけで決めないでください。付録の「保守を含めた総額の試算」の見出しと計算式を使うと、年数を変えて比べられます。

# 年数は、自分たちの入れ替えの時期で決める

計算に使う年数は、業者が勧める年数ではなく、自分たちがいつ入れ替えるかで決めます。

  • 機器の寿命や、製品の保守が終わる時期
  • 組織の中期の計画(拠点の増減、事業の変化)
  • ほかのシステムの入れ替えの時期(まとめて入れ替えると効率が良い)

5年で入れ替える予定なのに、7年の契約を前提にした割引を受けると、途中で解約するときに違約金がかかることがあります。

# 保守の中身を確かめる4つの観点

保守の契約では、費用だけでなく、中身を確かめます。

  • 対応の方法(確かめること:駆けつけ(現地に来てくれる)か、電話か、メールか)
  • 対応の時間(確かめること:何時から何時まで受け付けるか。平日だけか)
  • 対応の日数(確かめること:365日か、営業日だけか)
  • 復旧の早さ(確かめること:自分たちが許せる復旧までの時間に合うか)

最後の「復旧の早さ」が特に大事です。自分たちのシステムが、止まってから平均どれくらいで戻せているか(平均の復旧時間)、そして業務として何時間まで止まっても耐えられるかを、先に整理しておきます。

# 止められないシステムは、保守も止めない

停止による影響が極めて大きいシステムでは、機器の二重化や自動切替、保守の365日・24時間対応を有力な選択肢として検討します。必要な構成は、停止を許容できる時間、代替運用の可否、予算に応じて決めます。

機器を二重にしても、保守が平日の昼間だけなら、夜や休日に両方が止まったときに直せる人がいません。

# 業務と保守がずれるときは、経営者にリスクの合意を取る

費用の都合で、業務の時間と保守の時間がずれることもあります。例えば、システムは1年中動いているのに、保守は年間200日程度の営業日の、9時から18時だけ、という場合です。

このときは、ずれをそのままにせず、経営者にリスクの合意を取ってください。

このシステムは1年中動いていますが、保守は営業日の9時から18時だけの契約です。夜間や休日に故障した場合、翌営業日まで復旧できない可能性があります。その間は〇〇の業務を紙で行う想定です。このリスクを承知のうえで、この契約で進めてよいでしょうか。

担当者だけでリスクを抱えないことが大事です。合意を取っておけば、実際に夜間に止まったときも、決めた手順で落ち着いて対応できます。

# 業者との関係は、次の案件の武器になる

最後に、業者との関係についての実際にあった話です。

ある物流の会社で、倉庫の管理のシステムを改修したとき、以前の契約で約束されていたのに実施されていなかった作業があることが分かりました。そのことを冷静に伝えて交渉し、今回の改修の一部を無償で対応してもらいました。契約の中身を正確に把握していること自体が、交渉の材料になるのです。

また、一度きちんとした取引をした業者は、次の案件で早く、最初から良い条件で提案してくれることがあります。値切るだけの交渉ではなく、依頼書を丁寧に作り、約束を守り、支払いを確実に行うことが、長い目で見て一番の値下げになります。

# AIで時間を減らす

  • 見積もりの比較:複数の見積もりの明細を表にして渡し、「工程ごとに、物と工数に分けて並べ、差が大きいところと、片方にしかない項目を挙げて」と頼みます。
  • 質問の準備:差が大きい項目を渡し、「業者に、その理由を具体的に確かめる質問を作って」と頼みます。
  • 依頼書の下書き:システム台帳・業務フロー・要件の一覧を渡し、「依頼書の項目に沿って下書きして。あいまいな所は〔要確認〕と書いて」と頼みます。〔要確認〕の箇所を埋めることが、見積もりを下げる作業になります。
  • 注意:見積もりの金額や契約の条件は、多くの場合、外に出してはいけない情報です。AIに入れる前に組織のルールを確かめ、必要なら業者名や金額だけでなく、契約条件・構成情報・個人情報なども除き、外部サービスへの入力が許可された情報だけを使います。

第2章 ヒアリングの漏れを防ぐチェックシート

業務の聞き取りでは、どれだけ丁寧に聞いても、漏れが出ます。漏れは、導入した後に「この処理ができない」「この書類が作れない」という形で表に出てきて、追加の費用や手戻りになります。

ここでは、筆者が聞き取りのたびに使っている、漏れを防ぐ観点とコツをまとめます。付録にも、表計算ソフトに貼り付けて使える形で、同じ内容のチェックシートを入れています。

# 漏れを防ぐ8つの観点

# 1. 時期:毎日の業務だけを聞いていないか

  • ☐ 毎日・毎週・毎月の業務を聞いた
  • ☐ 月末・月初めの締めの業務を聞いた
  • ☐ 年に1回の業務を聞いた(年度末、決算、年末の手続き、賞与、契約の更新など)
  • ☐ 不定期の業務を聞いた(監査、行政の検査、制度の変更への対応、災害・障害のとき)

# 2. 例外:普段と違う処理を聞いたか

  • ☐ 取り消し・やり直しの処理を聞いた
  • ☐ 締めた後に直す処理を聞いた
  • ☐ 急ぎの処理を聞いた(手順が省かれることはないか)
  • ☐ 休日・夜間の処理を聞いた
  • ☐ 間違えたときに、どう気づき、どう直すかを聞いた

# 3. 対象の違い:人や物の種類ごとの違いを聞いたか

  • ☐ 雇用の形・契約の種類ごとの違いを聞いた
  • ☐ 途中で入った人・辞めた人・異動した人の扱いを聞いた
  • ☐ 拠点・部門ごとの違いを聞いた(同じ業務でも、やり方が違うことがある)

# 4. 人:誰が関わっているかを聞いたか

  • ☐ 担当者と、その代わりの人を聞いた
  • ☐ 確認・承認する人を聞いた
  • ☐ 担当者が休んだとき、どうしているかを聞いた
  • ☐ 「〇〇さんに聞く」と言われた人に、直接聞いた

# 5. 紙と書類:システムの外にあるものを聞いたか

  • ☐ 紙の書類・台帳・印鑑を使う場面を聞いた
  • ☐ 個人で作っているExcelやメモを聞いた(パソコンの中だけにあるもの)
  • ☐ 外に出す書類を聞いた(役所、銀行、取引先、顧客)
  • ☐ 書類の保存のルール(期間・場所)を聞いた

# 6. データのつながり:どこから来て、どこへ行くかを聞いたか

  • ☐ データの入力元(どこから受け取るか)を聞いた
  • ☐ データの出力先(どこへ渡すか)を聞いた
  • ☐ 外の組織とのやり取り(役所への報告、銀行の振込、取引先との受発注)を聞いた
  • ☐ 「念のため」突き合わせている作業を聞いた

# 7. 今の良いところ:なくなると困るものを聞いたか

  • ☐ 「今のシステムで、なくなると困る機能・画面は何ですか」と聞いた
  • ☐ 「今のやり方で、うまくいっている工夫は何ですか」と聞いた
  • ☐ 新しい製品の候補で、それができるかを確かめた

# 8. 3つの層:層ごとに聞いたか

  • ☐ 経営層から、方針と中長期の目標を聞いた
  • ☐ 中間層から、改善したい点と欲しい機能を聞いた

# 漏れを減らす、聞き方のコツ

観点を押さえたうえで、次の聞き方を組み合わせると、漏れがさらに減ります。

  1. 実物を見せてもらう:書類・画面・Excelを、実際に見ながら聞く。話だけより、ずっと多くのことが分かります
  2. 1日を追う:「朝、出勤したら最初に何をしますか」から始めて、1日の流れを順に追う
  3. 1か月・1年を追う:カレンダーを見ながら、「この週は何がありますか」と月と年の行事を追う
  4. 「最後にやったのはいつですか」と聞く:年に1回の業務は、本人も忘れています。最後にやった日を聞くと、思い出しやすくなります
  5. 新人向けの資料を見せてもらう:手順書や引き継ぎのメモには、口では出てこない手順が書かれていることがあります
  6. 同じ業務を2人に聞く:同じ業務でも、人によってやり方が違うことがあります。違いが見つかったら、そこが確かめるべき点です
  7. 聞いた内容を、その場で図にする:話を聞きながら簡単な流れ図を描き、「こういうことですか」と確かめる
  8. 録音する(許可を取って):後で聞き返すと、その場では聞き流した大事な一言に気づくことがあります

# AIで時間を減らす

  • 漏れの確認:聞き取りのまとめを渡し、「この8つの観点(時期・例外・対象の違い・人・紙と書類・データのつながり・今の良いところ・3つの層)で、聞けていないことを挙げて」と頼みます。次の聞き取りの質問の一覧になります。
  • 年間の行事の洗い出し:業種と部門を伝え、「この部門で年に1回・不定期に発生しやすい業務の例」を挙げてもらうと、聞き忘れを防げます。ただし、組織ごとに違うので、必ず本人に確かめます。

  2. 保守を初期の費用と時間で決める:実際に使う年数の総額と、復旧の早さを確かめないと、後で困る

# 業者とのやり取り

  • ☐ 相見積もりを取り、明細を工程ごと・物と工数に分けてもらった
  • ☐ 価格の差が大きいところは、理由を納得できるまで聞いた
  • ☐ 安すぎる見積もりに、含まれていないものを確かめた
  • ☐ 連携は、出す側の仕様と見本のデータを先に渡した
  • ☐ 保守は、実際に使う年数の総額で比べた
  • ☐ 保守の対応の方法・時間・日数が、業務と復旧の早さに合うか確かめた
  • ☐ 業務と保守がずれる場合は、経営者にリスクの合意を取った

まとめ

  • 見積もりは工程ごと・物と工数に分けて比べ、差は納得できるまで聞く
  • 依頼書の具体性が高いほど、業者が見込むリスクを小さくできる
  • 保守は使う年数の総額と、復旧の早さで決める。ずれは経営者と合意する

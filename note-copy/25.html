最初の2週間でやること

全部を読み終える前でも、今日から始められることがあります。最初の2週間は、次の順に進めてください。

1週目：知る準備

  1. 1日目:目的を1文にする(手順1の型を使う)。仮で構わない
  2. 2日目:経営層に目的を見せ、トップから一言、全体に呼びかけてもらう約束を取る
  3. 3〜4日目:システム台帳(この記事の付録の見出しを使う)に、知っているシステムを全部書き出す。契約書も探す
  4. 5日目:部門の責任者に、聞き取り票(付録の見出しを使う)を先に渡しておく

2週目：小さく計る

  1. 6〜8日目:部門の責任者から聞き取る。点線の矢印(手作業)が多そうな場所に印を付ける
  2. 9日目:一番手間がかかっていそうな作業を1つ選ぶ
  3. 10〜12日目:その作業を横で見て、3日分計る(付録の作業コストの計算を使う)
  4. 13〜14日目:年間の時間とコストを出し、経営層に「まずこれだけでも、年間これだけかかっています」と見せる

ここで示した14日間は着手のモデルです。休日や関係者の予定を除いた実働日数ではなく、関係部署の数によって聞き取りと計測にかかる日数は変わります。

2週目の最後の一言が、この取り組み全体の最初の推進力になります。1つの数字があるだけで、経営層の反応は大きく変わります。

はじめに知っておきたい、3つの層の考え方の違い

ここから下に有料部分を書いてください

10の手順に入る前に、1つだけ押さえておいてほしいことがあります。システムのことになると、経営層・中間層・現場層で、考えていることが大きく違うということです。

  • 経営層:中長期の目標、組織としての方針。よくある言葉は「上場の準備のため、国際的な会計の基準に合わせたい」「3年後に拠点を倍にしたい」
  • 中間層(部門の責任者):新しい機能、今のシステムの問題点の改善。よくある言葉は「この機能が欲しい」「今のここが使いにくいので直したい」
  • 現場層(担当者):仕事の内容が変わるか、仕事の量が増えるか減るか。よくある言葉は「覚えることが増えるのは困る」「結局、手間は減るのか」

どの層の考えも、間違ってはいません。問題は、それぞれが自分の層の考えだけで話してしまうことです。経営層は方針だけを言い、中間層は機能の要望を並べ、現場層は変化を警戒します。これをそのまま業者に伝えると、まとまりのない要望の山になります。

10の手順では、次のように3つの層の考えをつなぎます。

  • 手順1(目的):経営層の方針を、業務の言葉に直す
  • 手順2・3(地図と数字):中間層の要望と、現場層の手間を、同じ物差しで並べる
  • 手順7(合意。②で扱う):層ごとに説明の仕方を変える

# 現行の良いところは、見落とされやすい

もう1つ、よく起きることがあります。新しい製品が業務に合うかを確かめる段階(製品と業務の合う所・合わない所を確かめる段階)になって初めて、今のシステムの良いところに気づくことです。

中間層は「今の問題点」を、現場層は「今の不満」を話すので、聞き取りでは今の良いところがほとんど出てきません。ところが、新しい製品を触ってみると、「前はこれが1回でできたのに」「この画面はなくなるの」という声が次々に出てきます。

これを防ぐには、聞き取りの段階で「今のシステムで、なくなると困るものは何ですか」と必ず聞くことです。③の「ヒアリングの漏れを防ぐチェックシート」にも入れています。

# 手順1. 目的と後ろ盾を決める

# 実際にあった話：業界は初めて。それでも進められた理由

ある会社で、紙の帳票と台帳を全社で電子化する大きな導入を担当したときのことです。筆者にとって、その業界は初めてでした。プロジェクトを進める経験は積んでいましたが、その業界の業務の知識はほとんどありませんでした。最初は、どの部門からも「業界を知らない人に何が分かる」という目で見られていました。

それでも、本番の稼働までやり遂げることができました。支えになったのは、業界の知識ではなく、進め方の型でした。目的を決め、各部門から聞き取り、手作業を数字にし、合意を取ってから進める。この有料部分に書いている手順そのものです。業務の知識は、聞き取りを重ねるうちに後からついてきました。型があれば、業界を知らなくてもプロジェクトは進められるのです。

ただ、立ち上がりには時間がかかりました。少しだけ話を聞いてくれる人が各部門に1人ずついて、その人たちの小さな困りごとを1つずつ片付けながら、少しずつ協力を広げていきました。ある部門の責任者とは、最後まで意見がぶつかり続けました。

振り返ると、最初にトップから「この人に任せた。協力してほしい」と一言もらえていれば、立ち上がりの数か月はずっと短くなったはずです。型で進め方は補えても、後ろ盾は型だけでは埋められないと、このとき身にしみました。

# 何をするか

経営層と「何のために直すのか」を決めます。あわせて、トップから全体へ協力を呼びかけてもらいます。

目的があいまいなまま始めると、途中で必ず迷います。「AとB、どちらを先に直すか」を決めるときに、判断の物差しがないからです。

# 目的の3つの型

目的は、たいてい次の3つのどれかです。複数あっても構いませんが、一番大事なものを1つ決めてください。

  • 手間を減らす(例:残業を減らしたい、人が辞めても回るようにしたい、向いている物差し:作業時間、残業時間)
  • リスクを減らす(例:止まると困る業務を守りたい、情報漏えいを防ぎたい、向いている物差し:止まった回数、復旧までの時間)
  • 期限に間に合わせる(例:制度の変更、契約の終了、機器の寿命、向いている物差し:期限までに終わるか)

一番大事な目的が「手間を減らす」なら、優先順位は削減できる時間の大きさで決まります。「リスクを減らす」なら、止まったときの影響の大きさで決まります。目的によって、後の判断が変わるのです。

# 目的を1文にする

目的は、次の型で1文にまとめます。

〔いつまでに〕、〔どの業務の〕〔何を〕〔どれくらい〕にして、〔その結果どうなる〕ようにする。

例を挙げます。

1年以内に、注文の打ち直しと在庫の突き合わせをなくし、受注を担当する部門の残業を半分にして、繁忙期でも出荷が遅れないようにする。

数字は、この時点では仮で構いません。手順3で実際の数字が出たら、見直します。

# 成功の物差しを先に決める

目的と一緒に、「何が変われば成功か」も決めておきます。これを後から決めると、都合の良い数字だけを拾ってしまいがちです。

物差しは、2〜3個に絞ります。

  • 作業時間(月に何時間減ったか)
  • ミス・やり直しの回数
  • 特定の人がいないと止まる作業の数

# トップから呼びかけてもらう

聞き取りを始める前に、トップから全体へ一言もらいます。これがあるかないかで、現場の協力の度合いがまったく違います。

伝えてもらう内容は、3つで十分です。

  1. 何のためにやるのか(目的の1文)
  2. 誰が担当するのか(担当者の名前と立場)
  3. 聞き取りへの協力のお願い

呼びかけの文例です。

社員の皆さんへ。このたび、日々の事務作業の手間を減らすため、システムと業務の見直しを始めます。担当は〇〇さんです。今後、皆さんの業務について話を聞かせてもらうことがあります。困っていることを率直に伝えてください。今のやり方を否定するのではなく、より良く改善するために変えていく取り組みです。

最後の1文が大事です。「否定ではなく、改善のために変える」と明言してもらうと、現場は本音を話しやすくなります。

# AIで時間を減らす

  • 目的の1文を磨く:「〔目的の下書き〕を、いつまでに・何を・どれくらい・その結果どうなる、の形で3案にして」と頼むと、言葉の候補がすぐに出ます。
  • 呼びかけ文の下書き:目的・担当者・お願いの3点を渡し、「社員向けに、否定ではなく改善のために変える取り組みだと伝わる、やわらかい文にして」と頼みます。
  • 注意:組織名や個人名、内部の数字は、AIに入れる前に伏せてください。使ってよいAIのサービスと、入れてよい情報の範囲は、組織のルールに従います。

# つまずきやすい所

  • 目的が「システムを新しくする」になっている:それは手段です。新しくした結果、何が良くなるのかを目的にします。
  • トップが「任せた」で終わる:呼びかけをもらわないまま始めると、現場からは「担当者が勝手にやっていること」に見えます。
  • 目的を欲張る:手間もリスクも期限も、全部を一番にすることはできません。迷ったときにどれを取るかを決めておきます。

# 手順2. 現状を地図にする

# 実際にあった話：同じ質問でも、答えの粒度がばらばら

ある会社が別の会社をグループに迎えた後、事務の業務を統一するために、労務の業務を棚卸ししたことがあります。年末調整、給与計算、産休・育休、入職・退職、労災など、十数の業務の流れを整理しました。

苦労したのは、担当者によって答えの粒度がまったく違うことでした。ある人は手順を細かく話し、ある人は「いつも通りやっています」で終わります。そこで、質問を「次に何をしますか」の繰り返しに変え、実際の書類や画面を見せてもらいながら聞くようにしました。

別の会社では、地図を描いてみて初めて分かったこともありました。新しい取引先の登録を本社でしかできず、拠点の営業が注文を取ってから最初の出荷までに、何日もかかっていたのです。拠点で仮に登録し、本社が後から確かめる形に変えただけで、最初の出荷が目に見えて早くなりました。地図は、システムの問題だけでなく、運用の詰まりも見せてくれます。

# 何をするか

今あるシステム、データの流れ、手作業を書き出して、1枚の地図にします。困りごとを聞くだけでなく、「どこで何が起きているか」を見える形にするのが目的です。

# 聞き取りの順番

聞き取りは、次の順に進めます。

  1. 経営層:目的の確認と、経営から見た困りごと(2時間程度)
  2. 部門の責任者:部門の業務の全体像、使っているシステム(各60分程度)
  3. 現場の担当者:実際の作業の手順、手作業の箇所(各30〜60分程度)

上から順に聞くのは、全体像を先につかむためです。現場から始めると、細かい話に引き込まれて、全体が見えなくなります。

また、責任者と担当者は、できれば別々に聞きます。責任者の前では、担当者が本音を言いにくいことがあるからです。

# 聞き取り票(部門の責任者向け)

部門の責任者には、次の項目を聞きます。事前に渡しておくと、当日の話が早く進みます。

  • 業務の一覧(聞くこと:部門の主な業務を10個程度。毎日・毎週・毎月・毎年に分けて)
  • 使っているシステム(聞くこと:名前、何に使っているか、いつから使っているか)
  • 担当者(聞くこと:業務ごとに、誰がやっているか。その人しかできない業務はあるか)
  • 他部門とのやり取り(聞くこと:どの部門から何を受け取り、何を渡しているか)
  • 困りごと(聞くこと:時間がかかる、ミスが多い、特定の人しかできない業務)
  • 繁忙期(聞くこと:忙しくなる時期と、その理由)

# 聞き取り票(現場の担当者向け)

現場の担当者には、業務を1つ選んでもらい、手順を一緒に追います。

  1. その業務は、何がきっかけで始まりますか(紙が届く、月末になる、など)
  2. 最初に何を見ますか。どの画面、どの書類ですか
  3. 次に何をしますか(これを最後まで繰り返す)
  4. 途中で、別の画面や紙に書き写すことはありますか
  5. 途中で、数字が合っているか確かめることはありますか
  6. うまくいかないとき、どうしますか。誰に聞きますか
  7. 終わったら、誰に何を渡しますか

「次に何をしますか」を繰り返すのがコツです。担当者にとって当たり前の作業ほど、自分からは話してくれません。

# システム台帳を作る

聞き取りで出てきたシステムを、1つの表にまとめます。これが、後の手順10まで使い続ける「システム台帳」になります。

  • システム名(書く内容:社内での呼び名でよい)
  • 使っている部門(書く内容:主に使う部門と、見るだけの部門)
  • 用途(書く内容:何の業務に使っているか)
  • 業者(書く内容:導入した業者、保守している業者)
  • 契約(書く内容:月額・年額、契約の更新日、保守の終了日)
  • 扱うデータ(書く内容:社員、顧客、お金、在庫など)
  • つながり(書く内容:どのシステムとデータをやり取りしているか。自動か手作業か)
  • 社内の担当(書く内容:詳しい人、管理している人)
  • 置き場所(書く内容:社内のサーバー、クラウド、パソコン1台だけ、など)

契約の欄は、意外と埋まりません。契約書を探すと、保守の終了日が過ぎていたり、使っていないのに払い続けていたりするものが見つかることがあります。台帳を作るだけで、費用が下がることもあるのです。

# データの流れ図を描く

台帳ができたら、データの流れを図にします。難しく考える必要はありません。使う記号は3つだけです。

  • 箱:システム、Excel、紙の台帳
  • 実線の矢印:自動でデータが渡る
  • 点線の矢印:人が手で渡す(打ち直し、書き写し、ファイルの受け渡し)

描き方の手順です。

  1. 大きな紙かホワイトボードの真ん中に、一番よく使われるシステムを置く
  2. そこにデータを渡しているもの、受け取っているものを周りに置く
  3. 矢印を引き、実線か点線かを決める
  4. 点線の矢印に、誰が・どれくらいの頻度でやっているかを書き込む

描き終わると、点線の矢印が集まっている場所が見えます。そこが、手作業と煩雑さの中心です。

# 手作業を見つける5つのサイン

聞き取りでは、次の言葉が出てきたら、そこに手作業があります。

  • 打ち直し(よくある言い方:「こっちの画面を見ながら、あっちに入れる」)
  • 書き写し(よくある言い方:「紙に書いてから、あとでまとめて入れる」)
  • 突き合わせ(よくある言い方:「最後に、両方の数字が合っているか確かめる」)
  • 作り直し(よくある言い方:「毎月、Excelで集計表を作り直している」)
  • 問い合わせ(よくある言い方:「分からないときは〇〇さんに聞く」)

特に最後の「〇〇さんに聞く」は要注意です。その人がいなくなると止まる業務、つまり属人化している業務です。

# AIで時間を減らす

  • 聞き取りの記録をまとめる:録音を文字起こしし、「業務ごとに、きっかけ・手順・使う画面・書き写し・確認・渡す先の表にして」と頼むと、聞き取り票の形に整います。
  • システム台帳の下書き:聞き取りのメモを渡し、「台帳の項目(システム名・部門・用途・業者・契約・データ・つながり・担当・置き場所)で表にして。分からない欄は空けて」と頼みます。空いた欄が、次に聞くことです。
  • データの流れ図の下書き:「AからBへ手入力、BからCへ自動」のように文章で書き、図を描く記法(Mermaidなど)にしてもらうと、清書の手間が減ります。
  • 注意:録音や文字起こしには、個人の情報が多く含まれます。社外のAIに入れる前に名前を伏せるか、組織が認めた環境だけで扱ってください。

# つまずきやすい所

  • 困りごとだけを集めてしまう:困りごとの一覧だけでは、原因が見えません。システムとデータの流れを一緒に書き出してください。
  • パソコン1台で動いているものを見落とす:誰かのパソコンにだけ入っている集計用のExcelや、小さなソフトが、実は大事な役割を果たしていることがあります。「パソコンの中だけで使っているものはありますか」と必ず聞きます。
  • 現場の話を否定してしまう:「それは手順書と違いますね」と言うと、次から本当のことを話してもらえません。まずは、そのまま聞き取ります。

# 手順3. 課題を数字にする

# 実際にあった話：「いつも合わない数字」の正体

ある会社では、販売管理のシステムが持つ売掛金の数字と、経理の数字が、毎月必ず食い違っていました。担当者は「そういうものです」と言い、毎月、長い時間をかけて手で突き合わせていました。

原因を調べると、入金の記録の取り込み方と消し込みのやり方に、ずれがありました。銀行から受け取る入金のデータを元に、自動で消し込む小さな仕組みを作ったところ、突き合わせの作業はほぼなくなりました。

大事だったのは、作る前に「毎月何時間かかっているか」を数字にしていたことです。小さな仕組みでも、年間の時間に直すと、経営層がすぐに「やろう」と言える大きさになっていました。

# 何をするか

手順2で見つけた手作業や困りごとに、時間とお金の数字を付けます。この数字が、優先順位・合意・効果の確認のすべての土台になります。

# なぜ数字が必要なのか

自分の業務をうまく説明できる人は、多くありません。「大変です」「時間がかかります」という言葉だけでは、どの課題が重いのか比べられません。

また、声の大きい人の「大変」が優先されやすくなります。第1回で書いた「干渉期」と同じことが、改善の場でも起きてしまうのです。数字は、声の大きさに左右されない物差しになります。

# 作業を分けて、4つの数字を聞く

作業を細かく分けて、それぞれ次の4つを聞きます。

  • 頻度(聞き方:1日・1週・1か月に何回やりますか)
  • 時間(聞き方:1回に何分かかりますか)
  • 人数(聞き方:何人でやっていますか)
  • やり直し(聞き方:失敗してやり直すのは、10回に何回くらいですか)

例えば、書類のスキャンなら次のように聞きます。

  • 1日に何回スキャンしますか
  • 1回に何分かかりますか(機械の前まで行って、戻ってくるまで)
  • 読み取りに失敗して、やり直すのはどれくらいですか
  • スキャンしたあと、ファイルの名前を付け直したり、フォルダに移したりしますか

最後の質問のように、作業の前後にくっついている小さな作業も聞き出します。本人は「スキャン」の時間だけを答えがちですが、実際にはその前後に手間がかかっています。

# 年間のコストを計算する

4つの数字から、年間の作業時間とコストを出します。ここでの「1回の時間」は通常処理1回分とし、「やり直しの割合」は再作業が通常処理と同じ時間を要すると仮定した概算です。再作業時間が異なる場合は、実測した再作業時間を別に加算してください。

年間の作業時間 = 1回の時間 × 年間の回数 × 人数 × (1 + やり直しの割合)

年間のコスト = 年間の作業時間 × 1時間あたりの人件費

1時間あたりの人件費は、給与だけでなく、社会保険料なども含めた金額で考えます。正確な数字が出せない場合は、給与の1.2〜1.3倍程度を暫定値として使う方法もありますが、法定福利費や間接費は組織ごとに異なります。経理の担当者と相談して、組織で使う数字を1つ決めておくと、後で比べやすくなります。

計算の例です(数字は架空のものです)。

  • 作業(数字:メールやFAXで届いた注文を、販売管理のシステムに打ち直す)
  • 1回の時間(数字:注文1件あたり3分)
  • 回数(数字:月に200件 × 12か月 = 年間2,400回)
  • 人数(数字:1人)
  • やり直し(数字:10回に1回(確認と修正))
  • 年間の作業時間(数字:3分 × 2,400回 × 1人 × 1.1 = 7,920分 = 約132時間)
  • 1時間あたりの人件費(数字:2,500円(仮))
  • 年間のコスト(数字:約33万円)

これに、月末の在庫の突き合わせ(毎月4時間)が加われば、さらに年間48時間・12万円が増えます。1つ1つは小さく見えても、積み上げると、システムの費用と比べられる大きさになることが分かります。

# 聞くだけで足りなければ、計る

聞き取りの数字は、ずれることがよくあります。本人の感覚より、実際は長いことも短いこともあります。

大事な作業は、横で見て実際に計ります。やり方は簡単です。

  1. 計る作業を決め、本人に「横で見させてください」と伝える(目的は改善であり、評価ではないことを必ず伝える)
  2. ストップウォッチかスマートフォンで、作業の始まりから終わりまでを計る
  3. 途中で、何をしていたかをメモする(画面を探していた、電話で中断した、など)
  4. 少なくとも3日分、できれば忙しい日と普通の日の両方で計る
  5. 平均を出す

計ってみると、「作業そのもの」より「探す」「待つ」「確かめる」に時間がかかっていることがよくあります。これも、改善の大事な手がかりになります。

# 説明が苦手な人への聞き方

「普段、どれくらいかかりますか」と聞くと、多くの人は答えに困ります。次のように聞き方を変えると、答えやすくなります。

  • 「昨日はどうでしたか」と具体的な日を聞く:普段より、昨日のほうが思い出しやすい
  • 「一番大変だった月は」と極端な例を聞く:繁忙期の数字が分かる
  • 「5分くらいですか、30分くらいですか」と選択肢を出す:ゼロから答えるより楽
  • 画面を一緒に見ながら聞く:手順を思い出しやすい

# 見えにくいコストも書き出す

作業時間のほかにも、数字にしにくいコストがあります。金額にできなくても、一覧に書き出しておきます。

  • ミスの後始末:誤った給与の修正、取引先への謝罪など
  • 残業:作業が月末に集中して発生する残業
  • 引き継ぎ:担当が変わるたびに、教えるのにかかる時間
  • 属人化のリスク:その人が休んだり辞めたりしたときに止まる業務

特に属人化のリスクは、経営層に響きやすい項目です。「〇〇さんが1か月休んだら、この業務は止まります」という一言は、金額以上の重みがあります。

# AIで時間を減らす

  • 計算の確認:4つの数字と式を渡し、「この計算に誤りがないか、年間の時間とコストを確かめて」と頼みます。表計算の式も作ってもらえます。
  • 聞き方の練習:「説明が苦手な担当者に、作業の頻度と時間を聞く質問を10個」と頼むと、聞き取りの準備が早くなります。
  • 注意:計った数字そのものは、AIに推測させないでください。AIは計算と整理の補助に使い、数字は必ず現場で取ります。

# つまずきやすい所

  • 数字を出すのを面倒がって省く:省くと、手順6の優先順位も、手順7の合意も、手順9の効果確認も、すべて感覚頼みになります。この有料部分で一番強調したいのが、この手順です。
  • 計られる側が身構える:「仕事ぶりを評価されている」と感じると、普段と違う動きをします。目的を丁寧に説明し、結果は本人にも見せます。
  • 繁忙期を見落とす:普段の数字だけで判断すると、本当の負担を見誤ります。月末・年度末など、忙しい時期の数字も必ず聞きます。

# 手順4. 根っこの原因をまとめる

# 実際にあった話：不具合の山の、たった2つの根っこ

複数の拠点を持つある会社で、入れたばかりの勤怠のシステムが現場に浸透せず、苦情が山のように出ていました。導入を担当した人が辞めた後、誰も手を付けられない状態でした。

苦情を1つずつ並べると、年休の日数が合わない、入職日がずれている、シフトと勤怠の種類が合わない、と何十件もありました。しかし、まとめてみると、根っこは導入時の設定の誤りと、担当者がいなくなって誰も直せなかったことの2つだけでした。

全部のデータを一度取り出して直し、入れ直すことで、苦情の大半が一度に消えました。そのうえで、「設定の修正 → シフトの運用 → 申請の流れ → 給与とのつなぎ」の順に段階を分けて立て直しました。

# 何をするか

手順2と3で集めた個別の課題を並べ、共通する原因にまとめます。個別の課題を1つずつ直すのではなく、原因を1つ直すと、複数の課題が一度に消えるところを探します。

# 課題をカードにして、まとめる

やり方は、次の通りです。

  1. 課題を1つずつ、付箋かカードに書く(1枚に1つ。手順3の年間コストも書く)
  2. 机やホワイトボードに全部並べる
  3. 「同じ原因から来ていそうなもの」を近くに集める
  4. 集まったグループに、原因の名前を付ける
  5. グループごとに、年間コストを合計する

この作業は、1人でやるより、2〜3人でやるほうがうまくいきます。部門の違う人が入ると、「それはうちの課題とも同じ原因だ」という気づきが出てきます。

# 「なぜ」を3回繰り返す

原因が分からないときは、「なぜ」を繰り返します。よく「5回」と言われますが、実務では3回程度で根っこに届くことが多いです。

例です。

  • 課題：月末の棚卸しで、システムの在庫と実際の在庫が合わず、調べるのに丸1日かかる
  • なぜ1:出荷の記録を、倉庫のExcelと販売管理のシステムの両方に入れていて、片方の入れ忘れが起きるから
  • なぜ2:倉庫のExcelと販売管理のシステムがつながっていないから
  • なぜ3:商品の情報(商品コード・単位・保管場所)が、それぞれに別々に登録されていて、照らし合わせられないから

最後の「なぜ3」が根っこです。ここまで来ると、「システムをつなぐ」の前に「商品の情報を1か所にまとめる」が必要だと分かります。

# よくある4つの根っこ

筆者の経験では、煩雑になったシステムの根っこは、だいたい次の4つのどれかです。

  • 同じ情報が何か所にもある(見分け方:同じ内容を複数の画面で入力している、起きていること:打ち直し、数字のずれ、突き合わせ)
  • データの持ち主が決まっていない(見分け方:「どっちが正しいの」と聞く場面がある、起きていること:修正のたびに混乱、誰も責任を持たない)
  • 特定の人しか分からない(見分け方:「〇〇さんに聞いて」が多い、起きていること:休むと止まる、引き継げない)
  • 決まりがない(見分け方:部門ごとに勝手にシステムやExcelを作る、起きていること:同じものが増え続ける)

4つ目の「決まりがない」は、ほかの3つを生み出す元になっていることが多いです。これは②の手順10で対処します。

# 原因と課題の対応表

最後に、原因と課題の対応表を作ります。これが、手順5・6の材料になります。

  • 商品と取引先の情報が3か所にある(つながっている課題:在庫の突き合わせ、取引先の3重登録、請求書の作り直し、年間コストの合計:〇〇時間・〇〇万円)
  • 請求の数字と会計の数字が別管理(つながっている課題:月次の突き合わせ、決算前の修正、年間コストの合計:〇〇時間・〇〇万円)
  • 〇〇の集計が1人のExcel頼み(つながっている課題:担当者不在時の停止、引き継ぎ困難、年間コストの合計:金額化できない(リスク大))

# AIで時間を減らす

  • 課題のグループ分け:課題の一覧を渡し、「同じ原因から来ていそうなものをまとめ、原因に名前を付けて。理由も添えて」と頼むと、カードを並べる前の叩き台になります。
  • 「なぜ」の深掘り:課題を1つ渡し、「なぜを3回繰り返して、仕組みの側の原因を考えて。人のせいにしないで」と頼みます。
  • 注意:AIのまとめは仮説です。最後は、現場を知る人と一緒に確かめます。

# つまずきやすい所

  • 原因を「システムが古い」で止めてしまう:古いことは、原因ではなく状態です。「古いと、何が困るのか」をもう一段掘ります。
  • 人のせいにする:「〇〇さんのやり方が悪い」は根っこではありません。その人がそうせざるを得ない仕組みのほうに、原因があります。
  • グループが多すぎる:原因が10も20もあると、手を付けられません。5つ程度にまとまるまで、統合します。

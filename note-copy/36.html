Workers AIって何？ まずは30秒で

Workers AIは、サーバーを用意せずに、AIモデルをAPIで呼び出せるCloudflareのサービスです。Workerと呼ばれる小さなプログラムから、数行でAIに質問できます。

気になるお金の話は、ここが一番のポイントです。1日10,000ニューロン(AIの利用量を測る単位)までは無料で、毎日リセットされます。私の試算では、短いやり取り1往復が10ニューロン前後ですが、これは当時の仮計算で、一般的な消費量を保証する数字ではありません。考えてから答えるタイプのモデルは、考えた分も消費するので、実際はもっと減るかもしれません。使うモデルや返事の長さで大きく変わるので、あくまで目安です。2026年11月9日に確認した公式料金ページでも、無料枠は1日10,000ニューロンです。ただしモデルごとの単価や支払方法の要件が異なり、特定モデルでは有料の支払方法またはAI Gatewayのプリペイドクレジットが必要です。最新の料金は、公式の料金ページで確認してください。

使った分は、ダッシュボード左メニューの「AI」から「Workers AI」を開くと確認できます。公式の案内でも、ニューロンの使用量はこの画面で見られるとされています。1日の上限に近づいていないか、ときどき見ておくと安心です。

無料プランのままなら、枠を使い切っても、勝手に課金されることはありません。上限を超えると、AIの呼び出しがエラーで失敗し、チャットが返事を返さなくなるだけです。翌日のリセット(日本時間の朝9時)で、また使えるようになります。通常のWorkers AI利用では、無料枠を超えて継続するにはWorkers Paid等の課金設定が必要です。ただし一部のモデルは支払方法の設定が必須で、AI Gatewayのプリペイド課金を利用する構成もあります。モデルごとの条件を事前に確認してください。

必要なのは、Cloudflareのアカウントだけです。私はドメインを買ったときのアカウントで、そのまま使えました。無料プランのままで大丈夫です。

ここだけ覚えて帰ってください。無料枠内で、無料で利用可能なモデルを選んで試すなら、AI推論の追加料金を抑えられます。料金条件はモデルごとに確認してください。

# この記事で作るもの
先に完成形を描いておきます。登場人物は3つだけです。

  1. ブラウザのチャット画面:メッセージを打って送るだけの、簡単な画面
  2. Worker:画面を配り、質問をAIに取り次ぐ小さなプログラム(1ファイル)
  3. Workers AI:実際に答えを考えるAIモデル

利用者が画面で質問を送ると、Workerが受け取ってAIに渡し、返ってきた答えを画面に戻す。この一往復が、チャットの正体です。むずかしいところは、ほとんどありません。

土台を作る。Hello Worldで2分

土台になるWorkerは、ダッシュボードで「Hello World」を選んで名前を付けるだけで作れます。コードは1行も書きません。

  1. Cloudflareにログインし、左メニューの「コンピュート」から「Workers & Pages」を開く
  2. 右上の青いボタン「アプリケーションを作成する」を押す
  3. 「Hello World を開始する」を選ぶ(テンプレート一覧ではなく、上のほうの選択肢です)
  4. Workerの名前を入れる。私は `my-ai-worker` にしました。あとで消す前提だったので気軽に付けています
  5. 「デプロイ」を押す

途中に「Cloudflare Accessで保護」というスイッチが出ますが、今回はオフのままにしました。試して消すだけなら、保護はいりません。ただし、オフのままだとURLを知っている人は誰でも使えます。この話は最後の章で改めて書きます。

ここだけ覚えて帰ってください。この時点では、まだAIにつながっていません。URLを開いても「Hello World!」と出るだけです。

AIをつなぐ。ここだけは名前が命

WorkerにAIを使う権利を渡す操作を、バインディングと呼びます。ここで付ける変数名と、コードでの呼び方が1文字でも違うと、動きません。そして私は、ここで最初にこけました。

手順はこうです。

  1. 作ったWorkerを開き、上のタブから「設定」を選ぶ
  2. 「バインディング」の「バインディングを追加」を押す
  3. 一覧から「Workers AI」を選ぶ
  4. 「変数名」の欄に、コードで使う名前を入れて「バインディングを追加」を押す

AIに教わったコードは `env["AI"].run(...)` と呼ぶ形でした。つまり変数名は `AI` にしないといけません。

ところが、私は変数名の欄に出ていたグレーの文字をそのまま信じて、追加ボタンを押してしまいました。そこには `MY_BINDING` と書かれていたのです。入力欄に最初から入っている薄い文字は、入力例(プレースホルダー)で、実際の値ではありません。それを値だと思い込んだ、というのが真相です。

登録後の一覧を見ると、名前の欄はやはり `MY_BINDING`。コードは `AI` を呼んでいるのに、登録された名前は別物でした。気づいたのは、この画面をAIに見せて指摘してもらったときです。ここで一人で気づけたら格好よかったのですが(笑)。

直し方は簡単です。

  1. 一覧右端のゴミ箱アイコンで、`MY_BINDING` の行を削除する
  2. もう一度「バインディングを追加」から「Workers AI」を選ぶ
  3. 変数名の欄をクリックして、自分で `AI` と打ち込む
  4. 追加して、一覧の名前が `AI` になっていれば完了

途中で黄色く「wrangler設定を更新してください」と出ますが、今回は無視して大丈夫です。Wranglerはコマンドラインで使う開発ツールで、ダッシュボードだけで作る今回の方法には関係がありません。

ここだけ覚えて帰ってください。コードの `env["AI"]` と、バインディングの変数名 `AI` は、1文字も違わず同じにします。グレーの文字は例です。

チャット画面のコードを貼る。1ファイルで完結

チャットの画面と、AIに質問を渡す窓口は、1つのファイルにまとめました。前半がAIを呼ぶ窓口(`/api/chat`)、後半がブラウザに出すチャット画面(HTML)です。

Workerの画面右上の「コードを編集する」を開き、エディタの中身を全部消して、次のコードを貼ります。

const MODEL = "@" + "cf/meta/llama-3.1-8b-instruct";

export default {
 async fetch(request, env) {
 const url = new URL(request.url);

 if (request.method === "POST" && url.pathname === "/api/chat") {
 const { messages } = await request.json();
 const result = await env["AI"].run(MODEL, {
 messages: [
 { role: "system", content: "あなたは親切なアシスタントです。日本語で簡潔に答えてください。" },
 ...messages,
 ],
 });
 return Response.json({ reply: result.response });
 }

 return new Response(HTML, { headers: { "content-type": "text/html; charset=utf-8" } });
 },
};

const HTML = `<!doctype html>
<html lang="ja">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Workers AI チャット</title>
<style>
 body{font-family:sans-serif;max-width:640px;margin:0 auto;padding:16px}
 .log{border:1px solid gray;border-radius:8px;padding:12px;height:60vh;overflow:auto}
 .u{color:blue;margin:8px 0}.a{margin:8px 0;white-space:pre-wrap}
 form{display:flex;gap:8px;margin-top:12px}
 input{flex:1;padding:10px;font-size:16px}
 button{padding:10px 16px;font-size:16px}
</style>
</head>
<body>
<h2>Workers AI チャット</h2>
<div class="log" id="log"></div>
<form id="f"><input id="q" placeholder="メッセージを入力" autocomplete="off"><button>送信</button></form>
<script>
const log = document.getElementById("log");
const messages = [];
document.getElementById("f").addEventListener("submit", async (e) => {
 e.preventDefault();
 const q = document.getElementById("q");
 const text = q.value.trim();
 if (!text) return;
 q.value = "";
 messages.push({ role: "user", content: text });
 log.insertAdjacentHTML("beforeend", '<div class="u"></div>');
 log.lastChild.textContent = "あなた: " + text;
 const res = await fetch("/api/chat", {
 method: "POST",
 headers: { "content-type": "application/json" },
 body: JSON.stringify({ messages }),
 });
 const { reply } = await res.json();
 messages.push({ role: "assistant", content: reply });
 log.insertAdjacentHTML("beforeend", '<div class="a"></div>');
 log.lastChild.textContent = "AI: " + reply;
 log.scrollTop = log.scrollHeight;
});
</script>
</body>
</html>`;

1行目のモデル名が、`@` を2つに分けた書き方になっているのは、この記事の表記の都合です。貼ればそのまま、ひとつながりの名前として動きます。

仕組みを、かんたんに読み解いておきます。

  • `fetch` の中では、送られてきた要求が「`/api/chat` への POST」かどうかを見ています。そうならAIに質問し、そうでなければチャット画面(HTML)を返します
  • `messages` は、これまでのやり取りの全部です。画面側が毎回、会話の履歴をまるごと送ってくるので、AIは前の話を踏まえて答えられます
  • 先頭の `system` の1行が、AIへの基本の指示です。ここを書き換えると、口調や役割を変えられます。「あなたは丁寧な敬語で答える相談役です」のように変えるだけで、人格が変わります
  • 画面側の表示は `textContent` で入れています。AIの返事をHTMLとして解釈させないためで、変なタグが混ざっても画面が崩れません

このコードのモデル名は、次の章で痛い目に遭います。先に動く完成形を知りたい方は、「動いた」の章の差し替えを先にどうぞ。

貼ったら、右上の「デプロイ」を押します。貼っただけでは反映されません。私は一度、ここで押し忘れました。URLを開いても「Hello World!」のままで、「あれ？」となったのは内緒です。

もうひとつ、順番にも注意があります。バインディングを追加する前にチャットを送ると、AIが見つからないというエラーになります。 先に前の章を終わらせてください。

ここだけ覚えて帰ってください。コードを貼ったら「デプロイ」。押さないと、画面は変わりません。

送信したら無反応。コンソールが赤く光った

バインディングを直し、コードを貼り、デプロイも済ませました。チャット画面は出ました。ところが、メッセージを送っても、返事が返ってきません。

こういうときは、エディタ右側のプレビューの下にある「CONSOLE」欄を見ます。そこに、赤い文字でエラーが出ていました。

読んでみると、言っていることは単純でした。私が使っていたLlama 3.1 8Bのモデルは、2026年5月30日に廃止されていたのです。代わりのモデルはモデルカタログで探してほしい、とも書いてありました。エラー文がとても親切です。

つまり、2回目のこけ方は、1回目と同じでした。AIが教えてくれたコードを、そのままコピペして貼った。そのコードに書かれていたモデル名が、AIの知識の中では現役でも、現実にはもう古かったのです。AIも間違えます(笑)。

ここで覚えておくと役に立つ、画面が無反応のときの見方を整理しておきます。

  • まずCONSOLE欄を見る:赤い文字があれば、そこに原因が書いてあります。英語でも、そのままAIに貼って聞けば、意味を教えてくれます
  • 次にバインディングの名前を見る:設定タブの一覧で、名前が `AI` になっているか
  • それから、デプロイしたか:貼っただけで押し忘れていないか
  • 最後に、モデル名:公式のカタログに、いまも載っているか

今回は上から4番目で当たりでした。順番に潰していけば、迷いません。

ここだけ覚えて帰ってください。AIのモデルには賞味期限があります。コードに書いたモデル名は、動かなくなったら疑って、公式のカタログで確かめましょう。

立て直す。モデルカタログで選び直す

【2026年11月9日追記・重要】この記事で使用した @cf/qwen/qwen3-30b-a3b-fp8 は、Cloudflareの2026年11月5日の告知で11月20日廃止予定となりました。11月20日以降はHTTP 410（エラー5028）になる予定です。以下は執筆当時の動作記録として残していますが、いま新規に構築する場合は公式モデルカタログから継続提供されるモデルを選び、モデルID・応答形式・料金を再確認してください。

代わりのモデルは、公式のモデルカタログから選びます。私が開いたときは73個ありました。全部は読めないので、まず用途に合わないものを外していきました。

  • 状態と条件から判断や数値を返す特化型のモデル(会話には使えません)
  • 音声エージェント向けのモデル
  • 説明に出てくる言語が欧州中心で、日本語が期待しにくいモデル

残った候補の中から、私は `qwen3-30b-a3b-fp8` を選びました。理由は3つです。

  1. 現行のモデルで、廃止の表示が出ていない
  2. 料金が安い
  3. Qwen系は日本語が比較的強い傾向がある(これは期待で、確かめるのはこれからです)

料金は、公式の料金ページではこうなっています。比べた相手は、大きいぶん賢そうな `gpt-oss-120b` です。

  • qwen3-30b-a3b-fp8(入力(100万トークンあたり):$0.051、出力(100万トークンあたり):$0.335、ひとこと:今回の選択。推論に対応)
  • gpt-oss-120b(入力(100万トークンあたり):$0.35、出力(100万トークンあたり):$0.75、ひとこと:大きいが、入力の単価は約7倍)

もうひとつの候補だったLlama 3.3 70Bの高速版は、ニューロン換算で `qwen3-30b-a3b-fp8` の約6〜7倍の消費でした。無料枠がすぐ尽きるので、今回は見送りです。

カタログでモデルのページを開くと、モデル名がコードに書く正式な形で載っています。これをコピーしておきます。コードでは `cf/qwen/qwen3-30b-a3b-fp8` の先頭に `@` を付けた形になります。

選び方をまとめると、こうなります。

  • まず「いま使えるか」:廃止の表示がないか
  • 次に「用途」:会話なのか、画像なのか、音声なのか
  • それから「料金」:無料枠で遊ぶなら、小さめから試す
  • 最後に「日本語」:説明の対応言語を見て、日本語が入っていそうか

ここだけ覚えて帰ってください。モデルは「賢さ」だけでなく、「料金」と「用途」で選びます。無料枠で遊ぶなら、小さめから試すのが正解です。

動いた。日本語で返事が返ってきた

直す場所は、コードの2か所だけです。エディタで、1行目のモデル名と、返事を取り出す行を置き換えます。

1行目(モデル名)を、これに差し替えます。

const MODEL = "@" + "cf/qwen/qwen3-30b-a3b-fp8";

返事を返す行(`return Response.json({ reply: result.response });`)を、これに差し替えます。

return Response.json({ reply: result.response ?? result.choices?.[0]?.message?.content ?? JSON.stringify(result) });

返事の行を変えたのは、新しいモデルは返事のデータの形が、以前のモデルと違うことがあるからです。どちらの形でも拾えるようにしておけば、取り出し方で悩まずに済みます。最後の `JSON.stringify(result)` は保険で、どちらの形でもなかったときは、中身をそのまま画面に出します。何が返ってきたのかが見えるので、調べるときの手がかりになります。

右上の「デプロイ」を押して、チャットに「テスト」と送ってみます。

返ってきました。「テストを受けました。何かご質問がありますか？」と、自然な日本語で。エラーも、新しい送信分からは出ていません。

お、割とすんなり動きましたね。

ちなみに、動作確認でどれだけ無料枠を使ったのか。ダッシュボードの使用量欄を見ると、ログの記録(可観測性イベント)は33件で、1日の上限200,000件に対してごくわずかでした。ただしこれはログの件数で、AIの無料枠(ニューロン)とは別の数え方です。ニューロンの使用量は、左メニューの「AI」から「Workers AI」で確認できます。当時の私の画面では、使用ニューロンは66.72で、1日の無料枠10,000のうち約0.7%でした。これは実測画面の読み取りであり、直前の「1往復10ニューロン」という試算とは別の数字です。何回かチャットを試した程度なら、無料枠にはほとんど響きません。

ここだけ覚えて帰ってください。直すのは2か所だけ。モデル名と、返事の取り出し方です。

ちょっと待って。そのお店、本当にありますか？

調子に乗って、「京都駅近くのイタリアン探して」と聞いてみました。すると、それらしいお店の名前が3つ、雰囲気の説明つきで並びました。

でも、これは信用してはいけません。このチャットは、ウェブを検索していません。モデルが学習した知識だけで答えているので、お店の名前も、実在するかどうか分からないのです。しかもこのモデルは2025年4月に公開されたもので、学習データは2025年3月ごろまでとされています(開発元の公式発表ではなく、第三者サイトの情報です)。回答の最後に「口コミや最新情報を確認してください」とあるのは、確認できないことの裏返しでした。

というわけで、実際に調べてみました。京都駅から半径2km以内を、地図データと、グルメサイトで検索しました(2026年10月25日時点)。

結果は、3つとも見つかりませんでした。AIが挙げた3つの店名のどれも、京都駅周辺に同じ名前のお店はありません。名前の似た別のお店は出てきましたが、どれも京都駅から離れた場所にありました。一方、京都駅直結の百貨店の10階には、実在するイタリアンがありました。AIは、実在する店名を挙げる代わりに、それらしい店名を作ってしまったようです。

ただし、これは「どこにも存在しない」という証明ではありません。検索サイトや地図に載っていない小さなお店までは確かめられていません。AIが挙げた名前が、たまたま別の街に実在する可能性もあります。分かったのは、京都駅周辺では見つからなかったところまでです。

つまり、素のチャットが得意なのは、文章の下書き、要約、言い換え、考えを整理する相談相手のような仕事です。最新のお店の情報を調べるような仕事には、向いていません。

素のチャットに試してみてよかった頼みごとを、並べておきます。

  • 「この文章を、もう少しやわらかい言い方に直して」
  • 「次の箇条書きを、3行の挨拶文にまとめて」
  • 「会議の議題を5つ、思いつくだけ出して」

逆に、避けたほうがいい頼みごとはこちらです。

  • 「近くのお店を探して」「今日の営業時間は？」のような、最新の情報
  • 数字の根拠や、固有名詞を含む事実の確認
  • 法律・医療・お金に関わる判断の決め手

ただ、ここには続きがあります。調べさせたい情報を、あらかじめ読み込ませておくという方法があります。次の章で触れます。

ここだけ覚えて帰ってください。AIの答えは、最新情報や固有名詞ほど、確かめてから使います。

ここまでで、自分専用のチャットは立ち上がりました。この章は、ここから広がる使い方の紹介です。公式のドキュメントで確認した範囲で書いていて、私自身はまだ試していない部分があります。その点は正直に書いておきます。

# 1. ホームページに埋め込む
いちばん手軽なのは、`iframe` で自分のサイトにチャット画面をはめ込む方法です。今回のWorkerは、ふつうのWebページを返しているだけなので、考え方としてはこれで済みます。

<iframe src="自分のWorkerのURL" width="100%" height="600" style="border:0"></iframe>

ただし、私は記事を書いた時点で、自分のサイトでの表示確認までは終えていません。公開する前に、必ず表示を確かめてください。また、誰でも使える状態になるので、使いすぎ対策(回数の制限など)も考える必要があります。

# 2. ホームページの内容を、あらかじめ読ませる
素のチャットは、先ほどのイタリアンのように、知らないことを知っているふりをします。そこで、自分のサイトの内容を先に読み込ませておけば、「料金は？」「対応エリアは？」といった質問に、サイトの内容に沿って答えさせられます。

この仕組みを、RAG(検索で拾った資料を渡して答えさせる方法)と呼びます。CloudflareにはAI Search(旧AutoRAG)という機能があり、ウェブサイトをデータソースにできます。ページを自動で巡回して取り込んでくれます。条件は、同じCloudflareアカウントに登録済みのドメインであることです。

# 3. 社内マニュアルを読ませる
ファイルを読み込ませる方法もあります。R2というストレージのバケットから、Markdown、テキスト、HTML、PDF、Word、CSV、JSONを取り込めます。手順書を入れておけば、新人の質問に答える窓口になります。

# 4. 使い始める前の注意

  • AI Search自体は、公開ベータの間は制限内で無料ですが、回答の生成にはWorkers AIの無料枠を使います。最新の条件は公式で確認してください
  • 社内マニュアルを読ませたチャットを、誰でも開けるURLのまま置いてはいけません。ログインした人だけに絞る設定(Cloudflare Access)を使います
  • 個人情報や機密を含む資料は、そもそも入れません。試すときは、公開してよい資料で

ここだけ覚えて帰ってください。素のチャットに「自分の資料」を持たせると、できることが一気に広がります。ただし、公開範囲には気をつけて。

後片付け。試しただけなら、消しておく

今回のWorkerは、保護を付けていません。つまり、URLを知っている人なら誰でもチャットを使え、そのぶんは自分の無料枠から減っていきます。記事やSNSにURLを載せるのは避け、試し終わったら消しておくのが安全です。

Workerの消し方は次のとおりです。

  1. 消したいWorkerを開き、「設定」タブを選ぶ
  2. いちばん下の「危険ゾーン」まで移動する
  3. 「削除」を押して、画面の案内に従う

消すと、そのURLは使えなくなります。作り直したくなったら、またHello Worldから2分で戻れます。

ここだけ覚えて帰ってください。試すのは気軽に、消すのも気軽に。公開したままにしないこと。

まとめ

  • 月額0円、サーバーなし、コードは1ファイル。自分専用のAIチャットは、思っていたよりずっと手軽に立ち上がった
  • こけた原因は2回とも、AIの答えをそのままコピペしたこと。名前を合わせ、モデルの賞味期限を疑い、画面のエラーを自分の目で読む
  • 素のチャットは最新情報や固有名詞が苦手。自分の資料を読ませる方法で、できることが広がる
  • そして今回いちばんの収穫は、成功ではなく、こけた2回でした。AIが教えてくれたコードは、そのまま貼れば動く、とは限りません。この3つができれば、AIの答えは頼もしい相棒になります。
  • 自分の画面を持つと、次にやりたいことが自然に浮かんできます。サイトに埋め込む。資料を読ませる。専用の相談窓口に育てる。借り物ではない、自分の画面。ぜひ、2分から始めてみてください。

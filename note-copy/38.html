画像生成ツールは、思ったよりあっさり動きました。ここまでは前回の構築編のとおりです。

ところが、使いはじめると、エラーが次々に出ました。

連載「Cloudflare Workers AI」の第3回、失敗とコスト編です。この記事は、その失敗の記録です。踏んだエラーは5つ。どれも原因がわかれば短い話ですが、最初は何が起きているのかさっぱりでした。

最後に、いちばん焦った場面と、実際にかかるコストの数字をまとめます。同じところで止まる人の、時間の節約になればうれしいです。

この記事でわかること

  • 画像生成ツールで踏んだ5つのエラーの、症状・原因・直し方
  • 無料枠を超えたときに何が起きるか(無料プランと有料プランの違い)
  • モデルごとの、1日に作れる枚数の目安と、その数字の根拠

先に、5つのエラー早見表

あとで詳しく書く5つを、先に一覧にしておきます。

  • 5006(症状:余計な項目は受け付けないと言われる、原因:簡易モデルに、使えない項目(seed)を渡していた、直し方:seedを外す)
  • 3030(症状:画像の入力がモデルにないと言われる、原因:参考画像に対応していないモデルを選んでいた、直し方:モデルの振り分けを作る)
  • 3043(症状:内部エラーと出る、原因:Cloudflare側の一時的な不具合と見られる、直し方:もう一度実行する)
  • なし(症状:スマホで保存できない、原因:画像をデータのリンクにする方式が合わなかった、直し方:共有機能に切り替える)
  • なし(症状:消費の見積もりが大きく外れる、原因:見積もりの計算が間違っていた、直し方:実測を基準にする)

失敗1:seedを入れたら弾かれた(5006)

  • 症状:「失敗: 5006: Additional or unevaluated properties '/seed' at '/' not allowed」と出る
  • 原因:簡易モデル(FLUX schnell)は、プロンプトとステップ数しか受け付けない。そこにseedを渡していた
  • 直し方:schnellの呼び出しからseedを外した

エラー文を読むと、「'/seed' は許されていない」と、はっきり書いてあります。英語ですが、短くて正直です。

直した部分は、こうです。

// 直す前:seedを渡していた(5006で弾かれる)
resp = await env["AI"].run(MODELS.draft, { prompt: full.slice(0, 2048), steps, seed });

// 直した後:プロンプトとステップ数だけ
resp = await env["AI"].run(MODELS.draft, { prompt: full.slice(0, 2048), steps });

つまり、このモデルへの呼び出しではseedを指定できず、同じ画像を狙って再現する手段は限られます。今回のツールでは割り切りました。

もし同じ絵をもう一度作りたいなら、seedを受け付けるモデルを使います。私のツールでは、参考画像ありの簡易と高精度が、これにあたります。

失敗2:参考画像を渡したら、モデルが「画像なんて知らない」(3030)

  • 症状:「失敗: 3030: Model input is not valid: input tensor `image` is not present in the model」
  • 原因:ネガティブプロンプト用にSDXL Lightningを使っていたが、このモデルは参考画像に対応していなかった
  • 直し方:モデルの振り分けを作った

「入力のテンソル image が、モデルに存在しない」。かみ砕くと、「このモデルに、画像を渡す口はありません」という意味です。

振り分けはこうです。

  • 参考画像ありの簡易:FLUX.2 klein 4B
  • 参考画像ありの高精度:FLUX.2 klein 9B
  • ネガティブあり・参考画像なしの簡易:SDXL Lightning
  • それ以外の簡易:FLUX schnell

コードの上では、先に条件を整理してから、呼び分けています。考え方だけ抜き出すと、次のようになります。

const useRef = typeof body.refImage === "string" && body.refImage.length > 100;
const neg = String(body.negative || "").trim().slice(0, 500);

if (mode === "draft" && !useRef && !neg) {
 // 参考画像もネガティブもない簡易 → schnell
} else if (mode === "draft" && !useRef) {
 // ネガティブだけある簡易 → SDXL Lightning
} else {
 // 参考画像がある簡易(klein 4B)と、高精度(klein 9B)
}

モデルごとにできることが違う。繰り返し踏むと、さすがに身につきます。

# モデルを選ぶ前に確かめること
今なら、モデルを決める前に、次の3点をカタログで見ます。

  1. 入力に何を渡せるか:文字だけか、画像も渡せるか
  2. 使える項目はどれか:seed、ステップ数、ネガティブプロンプトなど
  3. 出力の形は何か:画像のデータか、文字か

この3つが違うと、同じ呼び方をしても、エラーになります。失敗1も失敗2も、原因はここでした。

失敗3:理由がわからない「内部エラー」(3043)

  • 症状:「失敗: 3043: Internal server error」
  • 原因:Cloudflare側の一時的な内部エラーと見られる。こちらでは特定できない
  • 直し方:もう一度、実行する。時間をおけば直ることが多い

自動で再試行する仕組みを足す案もありますが、いまのところは入れていません。最初から完璧を目指さない。自分専用のツールなので、そこは割り切りです。

参考までに、再試行の仕組みは、次のような形で足せます。3043のような一時的なエラーだけを、間をあけて最大2回やり直し、ほかのエラーはそのまま返します。ダミーのAIで、「2回失敗して3回目に成功する場合」と「別のエラーはすぐ返す場合」の動きは確かめましたが、実際のWorkerには組み込んでいません。

async function runWithRetry(env, model, input, tries = 2) {
 for (let i = 0; i <= tries; i++) {
 try {
 return await env["AI"].run(model, input);
 } catch (e) {
 const msg = String(e && e.message ? e.message : e);
 const temporary = msg.includes("3043") || msg.includes("Internal server error");
 if (!temporary || i === tries) throw e;
 await new Promise((r) => setTimeout(r, 1000 * (i + 1)));
 }
 }
}

ただし、やり直しのたびに、無料枠のニューロンを使う可能性があります。高精度モードに入れるときは、回数を欲張らないほうが安全です。

失敗4:スマホで画像が保存できない

  • 症状:スマホで「保存」を押しても、画像が保存されない
  • 原因:画像をデータのURLでリンクにしていた方式が、スマホのブラウザでうまく動かなかった
  • 直し方:共有機能(Web Share API)で共有シートを開く形に変更。使えない環境では、ファイルとしてダウンロードする方式に切り替える

ツールを作ったのに、作った画像を手元にできないのは、いちばんもどかしい失敗でした。

直したあとの保存の部分は、こうなっています。

function saveImage(b64, mime, fname){
 try {
 var bin = atob(b64), n = bin.length, u = new Uint8Array(n);
 for (var i = 0; i < n; i++) u[i] = bin.charCodeAt(i);
 var blob = new Blob([u], { type: mime });
 var file = new File([blob], fname, { type: mime });
 if (navigator.canShare && navigator.share && navigator.canShare({ files: [file] })) {
 navigator.share({ files: [file] }).catch(function(){});
 return;
 }
 var url = URL.createObjectURL(blob);
 var l = document.createElement("a");
 l.href = url; l.download = fname;
 document.body.appendChild(l); l.click(); document.body.removeChild(l);
 setTimeout(function(){ URL.revokeObjectURL(url); }, 10000);
 } catch (e) {
 note.textContent = "保存に失敗しました。画像を長押し(右クリック)して保存してください";
 }
}

流れは、3段構えです。

  1. 共有機能が使える環境なら、スマホの共有シートを開く(写真アプリへの保存もここから選べる)
  2. 使えない環境なら、ファイルとしてダウンロードする
  3. それも失敗したら、「画像を長押しして保存してください」と案内する

上のコードの最後の `note` は、画面の別の場所にある、メッセージの表示欄です。単体では動かず、ツール全体の一部として動いています。

失敗5:見積もりが、だいぶ外れていた

  • 症状:簡易モード1枚あたり、60ニューロン程度のつもりだったのに、ダッシュボードでは約173ニューロンだった
  • 原因:見積もりの計算が間違っていた
  • 直し方:画面の説明文を直し、実測値を基準にした

ここで学んだことはひとつ。見積もりより、ダッシュボードの実測を信じる。それだけです。

当時、私の設定と画像サイズで使った概算式は、「19.2 + 38.4 × ステップ数」です。ステップ数が4なら、19.2 + 153.6 = 172.8。実測の約173と、ほぼ一致します。

この差が、次の焦りにつながりました。

山場：無料枠を超えたと言われ、課金を疑った

ある朝、ダッシュボードを開いて固まりました。やってしまった！

「本日のニューロン制限 10,000 を超えました。プランをアップグレードする」

黄色い警告です。超えたということは、課金されるのでは。そう思って、血の気が引きました。

調べてみると、答えは拍子抜けするものでした。

  • Workers Free:上限を超えると、その日の生成がエラーで止まる。課金はされない
  • Workers Paid:超えた分だけが従量課金。単価は1,000ニューロンあたり $0.011

自分は無料プランなので、何も起きませんでした。止まっただけです。

とりあえず、一安心。冷や汗はかきましたが、請求は増えません。課金を避けたい人は、この無料プランで続けるのが安全です。

# もし、有料プランだったら
念のため、有料プランの場合の計算も書いておきます。

  • 高精度を調子に乗って回し、一晩で約11,000ニューロンを使ったとします
  • 無料枠は10,000なので、超過は約1,000ニューロンです
  • 単価は1,000ニューロンあたり $0.011 なので、超過分は約$0.011

たとえば、1,500ニューロンの超過なら、約$0.02です。数字だけ見ると小さいですが、「いつの間にか請求が出る」のが不安な人は、無料プランのままがいちばんです。

コストの現実:1日10,000ニューロンで、何枚作れるか

無料枠は1日10,000ニューロンです。何枚作れるかは、モデルで大きく変わります。簡易モードなら約57枚、高精度モードなら7枚前後です。

  • FLUX.1 schnell(使う場面:簡易(枚数を回す)、1枚あたり(ニューロン):約173、1日の目安(枚):約57、根拠:ダッシュボードの実測)
  • FLUX.2 klein 4B(使う場面:参考画像ありの簡易、1枚あたり(ニューロン):約110、1日の目安(枚):約90、根拠:価格表から計算(未実測))
  • FLUX.2 klein 9B(使う場面:高精度(仕上げ)、1枚あたり(ニューロン):約1,364、1日の目安(枚):約7、根拠:価格表から計算(ダッシュボードとも整合))

SDXL Lightning(ネガティブ用)は、価格が公開されていないので表に入れていません。

1日の目安は、10,000を1枚あたりの数字で割って、小数点以下を切り捨てたものです。10,000 ÷ 173 は約57.8、10,000 ÷ 110 は約90.9、10,000 ÷ 1,364 は約7.3になります。

高精度モードの消費は、簡易の約8倍です。いったん調子に乗って高精度を回すと、あっという間に枠を使い切ります。実際には、一晩で約11,000ニューロンを使いました。

なお、2026年11月9日時点のCloudflare公式料金表では、Workers Paidの無料割当超過分は1,000ニューロンあたり $0.011 です。Workers Paid自体の月額料金や、別の有料サービスの費用とは分けて考える必要があります。無料で試したいなら、対象モデルが無料プランで使えることも先に確認します。

ダッシュボードの数字は、少し遅れてやってくる

ここで、はっきり伝えておきたいことがあります。

  • ダッシュボードの使用量は、少し遅れて反映される
  • こちらで表示している「推定使用量」は、あくまで目安です

使い切ったところでダッシュボードを見ると、「あと少し残っている」ように見えることがあります。高精度モードは、残りが少ないときは避けるのが安全です。

同じ失敗を避けるための、4つの習慣

5つの失敗と1つの焦りから、私が持ち帰った習慣を、並べておきます。

  1. エラー文は、そのまま全部読む。5006も3030も、原因はエラー文に書いてありました
  2. モデルを替えたら、入力の形も見直す。同じ呼び方が、別のモデルでも通るとは限りません
  3. 見積もりは疑い、実測を基準にする。ダッシュボードの数字は少し遅れるので、残りがぎりぎりのときは高精度を避けます
  4. 高精度は、残りを見てから回す。1枚で、簡易の約8倍を使います

まとめ：止まるだけ。だから、安心して遊べる

最初にあげた5つの失敗は、エラー文と使用量を一つずつ見れば対処の糸口がありました。無料枠の超過も、対象モデルをWorkers Freeで利用している範囲では、追加課金ではなく、その日の生成が制限されます。ただし、モデルによっては有料の支払方法が必要で、別の有料機能はこの話に含めません。

この実験で学んだことは、次の3つです。

  • モデルごとにできることが違う。振り分ける
  • 見積もりより、ダッシュボードの実測を信じる
  • 高精度モードは、簡易の約8倍を使う。回すときは残量を見る

無料で、自分だけの画像生成ツール。エラーを踏むだけの価値は、あります。

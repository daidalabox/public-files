連載「自動で株の売買を行う夢見る人」の第3回です。

ある朝、わくわくしながら、Claudeに聞きました。「ボット、結果はどう?」

返ってきたのは、たった一言。「注文なし」。

え? 何も、買ってないの?

この記事でわかること

  • AIの株自動売買ボットが、動いているのに何も買えなかった。その「犯人」は、慎重すぎる安全装置だった
  • 市場の恐怖度と、不正・急落のニュースという「二つの目」を足して、悪いニュースを避けるようにした
  • 作っただけでは安心できない。「動いている」と「効いている」は別物だった

わくわくして待った朝、返ってきたのは「注文なし」

この日は、朝からそわそわしていました。

AIが自分で考えて、自分で買う。その最初の成果が出ているはず。夢見る人の、いちばん夢見ている瞬間です。

ところが、結果は「注文なし」。

最初に浮かんだのは、これでした。「何か、暴落でもあったのかな?」

市場が荒れて、ボットが怖がって、買わなかった。そうであってほしい、とさえ思いました。それなら、ボットは「賢く見送った」ことになるからです。

でも、Claudeに「なんで?」と聞くと、答えは違いました。

暴落ではありませんでした。ただの、エラーでした。

そこからの流れは、こんな感じです。

  • 結果を聞いたら、「注文なし」
  • 暴落を疑ったけれど、違った。ただのエラーで、修正した
  • 気を取り直して実行したら、止まっていた。もう一度、修正した
  • そして、今度こそ

この「今度こそ」まで、けっこう長い道のりでした。この回は、その記録です。

エラーの正体:犯人は、二人いた

まず、ボットが元気かどうかを確認しました。自動で走る処理の履歴を見ると、並んでいるのはずらりと緑の印。失敗はありません。

「なんだ、元気じゃないか」と思いかけて、すぐに気づきました。元気なことと、買えていることは、別の話です。 注文の記録は、ゼロ。

動いているのに、買えない。いちばん気づきにくくて、いちばんお金の動かないタイプの故障でした。犯人は、一人ではなく二人いました。

# 犯人その1:週末をまたぐと、賞味期限が切れる

このボットには、「市場リサーチ」という別の部屋があります。ニュースを調べて、「この銘柄は避けたほうがいい」といった判定を、ファイルにして渡してくれる役目です。

そのファイルには、賞味期限がありました。作ってから、およそ1日半。しかもリサーチの更新は、平日だけです。

つまり、週末をまたぐと、月曜の朝には、賞味期限の切れたファイルしか残っていないのです。そして、ボットの設定は「期限が切れていたら、新しい買いは止める」。安全のつもりで入れた設定でした。

# 犯人その2:載っていない銘柄は、買わない

もう一つは、「リサーチに載っていない銘柄は、避ける扱いにする」という設定です。

ところが、ボットが毎日選ぶ買い候補は、日ごとに入れ替わります。リサーチのファイルに載っているのは、ごく少数の銘柄だけ。毎日の候補は、ほぼ全部が「載っていない」ので、ことごとく見送りになっていました。

どちらも、最初に作ったときは「慎重でいい設定だ」と考えたものです。二つ重なって、静かに、全部を止めていました。

# 教訓:安全装置は、「止める」側に寄せすぎない

ここで、ひとつ大きな学びがありました。

安全装置を「止める」側にだけ倒すと、安全装置が壊れたとき、全部が止まります。 壊れたのが安全装置なのか、ボット本体なのか、外から見ても分かりません。動いているように見えるぶん、気づくのが遅れます。

あなたの身の回りの仕組みにも、「何かあったら止まる」だけの安全装置、ありませんか?

直したこと:リサーチが無くても、動くように

まず、ボットがリサーチに頼りきりの状態をやめました。

  • 賞味期限が切れても、新しい買いは止めない
  • リサーチに載っていない銘柄は、「中立」として扱う

こう書くと、「安全装置を外したの?」と思われそうですよね。私も、ちょっと不安でした。

ただし、安全装置の一部を緩めたことは事実です。別の指標やニュース判定を足しましたが、リサーチが欠けても従来と同じ安全性を保てると確認できたわけではありません。 実際の判断記録で、代わりのチェックが正しく働くか検証する必要があります。そのために、二つの目を足しました。

ボット自身に足した、二つの目

# 一つ目:市場全体の「空模様」

個別の銘柄がどうであっても、市場全体が荒れているときは、買わないほうがいい日があります。台風の日に、遠出の予定を入れないのと同じです。

そこで、市場全体の「恐怖度」と「過熱度」を見ることにしました。

  • VIX(恐怖指数):投資家がどれだけ不安がっているかを表す、有名な指標です。公式の公開データから取り、取れなければ別の公開データで代用します
  • 市場全体の過熱度:代表的な株価指数の連動商品の値動きから、「上がりすぎていないか」を、ボットの手元のデータで計算します

警戒の水準になれば、同時に持つ銘柄の数を減らします。危険の水準になれば、新しい買いを止めて、持っているものの損切りを近づけます。基準にしている数字は、この連載の方針どおり、書きません。

ちなみに、もう一つ有名な「恐怖と強欲の指数」(あるニュースサイトが出しているもの)も使いたかったのですが、ボットが動いているサーバーからのアクセスは、断られました。 初期設定ではオフにして、取れたら使う、という扱いにしています。無料のデータは、こういうところが気まぐれです。

# 二つ目:候補と保有の「見出し」

もう一つの目は、ニュースです。買い候補と、いま持っている銘柄について、直近の見出しを集めます。

取得先は、検索ニュースの公開フィード(英語版)。無料で、登録もいりません。判定は、見出しの語の一致だけ。 AIには、読ませていません。

ただし、見出しの中に、その会社の名前か銘柄記号が入っているものだけを数えます。他社の記事を、うっかり数えないためです。

# 誤判定:「目標株価の引き下げ」が、ある会社と間違われた

ここで、笑える失敗がありました。

ある会社の名前は、英語では、ごく普通の言葉と同じ綴りです。そして、アナリストの記事には、よく「目標株価の引き下げ」という見出しが出ます。

ボットは、その見出しを、その会社のニュースだと思い込みました。 会社のことではなく、別の会社の目標株価の記事なのに。

直し方は、一語だけの会社名は、ふつうの言葉と間違えないよう、見出しの先頭にあるときや、「名前+株」「名前+決算」のような形のときだけ数える、というルールにすること。直したあとの試験では、その会社は、ちゃんと「問題なし」になりました。

# 共通のルール:「減らす・止める」にだけ使う

この二つの目には、共通のルールがあります。

ニュースも指標も、「買い増す」きっかけには使いません。 数量を減らす、買わない、保有なら手放す。厳しくする方向にだけ使います。

「このニュースは良さそうだから買おう」は、見出しの語の一致では、あまりにも危うい。ただし、売却・見送りの誤判定による機会損失もあり、見出しだけの判定には限界があります。

市場リサーチの役目:悪い話を、先に拾う

では、別の部屋の「市場リサーチ」は、何をしているのでしょうか。

役目は一つ。不正の情報や、株価が大きく下がりそうなニュースを拾って、買い候補から外すこと。 保有しているなら、手放すこと。

判定の段階は、ざっくり三つあります。

  • 数量を半分にする:格下げや、業績見通しの引き下げなど
  • 買わない:訴訟や調査、リコール、情報漏えいなどが、複数の報道で出ているとき。会計の疑いや空売り調査の報告のような重い話は、報道が一つでも買わない
  • 手放す:破産や不正会計、起訴など、重大な話が複数の報道で出ているとき

こちらも、判定は語の一致だけ。AIも有料のサービスも使いません。毎日の実行に加えて、3時間おきに見直し、見直すときは、判定を厳しくする方向にだけ更新します。 週末も動きます。

さらに、戦争、金利、原油という三つのテーマで、市場全体のニュースも見ています。ここが荒れていれば、市場全体の警戒を引き上げます。

「1日遅れ」にしない:連携の順番

もう一つ、こだわったことがあります。情報が1日遅れにならないこと。

ボットは毎日、夕方(日本時間の6時)に、米国の企業が公開している財務データを集めて、点数をつけ、順位をつけます。その結果で、買い候補の約30銘柄が決まります。

その直後に、候補と保有銘柄を、市場リサーチへ渡すようにしました。 渡されたリサーチは、その日のうちに、候補のニュースを調べ直します。順位が決まってから判断するまでの間に、悪いニュースを見逃さないためです。

最初は、「候補が変わった日だけ渡す」作りでした。でも、AIに話しているうちに、ふと思ったのです。

候補が入れ替わらなくても、急落のニュースは出ますよね?

その通りでした。入れ替わった日だけ調べる作りだと、入れ替わりのない日は、調べる時間が空いてしまいます。そこで、候補が変わらなくても、毎日渡す作りに変えました。

おまけとして、取得済みの決算予定日も、一緒に渡すようにしました。大型株の決算日が過ぎたままになっていて、数量が半分のまま、という状態を直すためです。

つまずいた三つの話

# つまずき1:「存在しません」と言われる

冒頭の「止まっている」の正体が、これです。連携を動かしてみると、いきなり「見つかりません」の返事。

調べると、原因はコードではなく、連携用の鍵(アクセストークン)の権限が、空っぽでした。作るときに、対象の保管庫と権限を選ぶ画面で、選び忘れていたのです。

ちなみに、権限がないとき、GitHubは非公開リポジトリへのアクセス権がないときなど、404（見つかりません）を返す場合があります。 非公開の保管庫を、持っていない人に見せないための仕様です。「見つかりません」と出たら、まず鍵の設定を疑うのが近道でした。

権限を直したら、一発で通りました。失敗したときに、確認する項目を表示するようにも直しました。

# つまずき2:「急落した」は、悪いニュースじゃなかった

悪材料の語に、「急落した」「暴落した」のような値動きの言葉を入れていたのです。

ところが、ある大型株で、「決算後に急落した」という見出しが、避けるべき銘柄の判定を引き起こしました。これは、すでに起きた値動きの記事です。先行きの悪材料の目印ではありません。 強気の記事にも、「急落は買い場」のように出てきます。

値動きの語は、すべて外しました。「何が起きたか」を示す語だけを残して、「どう動いたか」を示す語は外す。この線引きは、実際に出力を見てから気づいたことでした。

# つまずき3:決算日が、過ぎたまま

大型株4つは、設定ファイルに、決算の日付を人が書いています。その日付が、先日の決算で過ぎてしまい、「次の日付は不明」の扱いになっていました。不明だと、安全のために数量が半分です。

次の決算日は、各社がまだ公式に発表していません。推測の日付を書くのは、避けたい。そこで、すでに取得している決算カレンダー(推測を含みます)を、自動で渡して使う形にしました。

公式の発表が出たら、人が書き換えた日付のほうを、優先します。 推測は、あくまで仮置きです。

確かめられたこと、まだのこと

ここまで書いて、正直に線を引いておきます。

確かめられたこと

  • 筆者が実施した試験では、ボット側500件以上、リサーチ側100件以上が通りました（第三者による独立検証ではありません）
  • 本物の実行で、約30銘柄を市場リサーチへ渡す連携が成功しました。取得のエラーはなく、実行にかかった時間は約1分です
  • 決算日も、渡した結果が反映され、数量の絞りが解けました

まだ確かめられていないこと

  • ボットが、リサーチの結果を、実際の判断に使う場面(次の平日で確認します)
  • 悪い材料のある銘柄が、実際に「買わない」「手放す」になる場面。今回は、該当する銘柄がなく、試験の上でしか確かめていません

「作った。動いた。だから大丈夫」とは、まだ言えません。動くことと、効くことは、別です。

反省:同じ仕事を、二か所でやっている

最後に、自分で気づいた反省を書きます。

候補のニュースを調べる仕事を、ボット本体と市場リサーチの二か所でやっています。悪い言葉のリストも、設定が二つあります。片方だけ直すと、判定が食い違います。

連携を増やしたぶん、鍵の期限切れのような、失敗する場所も増えました。連携が失敗しても、ボットの判断が止まらない作りにはしてあります。でも、仕組みを足すほど、確認するものも増えます。

迷って、AIにも聞きました。「無駄が多くないか?」。答えは、「データの行き来そのものは軽い。問題は、仕事が二重なこと」でした。

今週は、あえて、このまま動かします。そして、市場リサーチの判定が、ボット単独にはない情報を実際に足したのかを、判断の記録から見て、整理するかどうかを決めます。

まとめ

  • 「動いている」と「買えている」は別。安全装置を「止める」側にだけ寄せると、壊れたとき、全部が静かに止まる
  • 悪いニュースの対策は、「減らす・止める」にだけ使う。ただし、見出しの語の一致には誤判定があるので、実際の出力を見て、語を磨き続ける
  • 仕組みを足すほど、確認するものも増える。あなたなら、二重の仕組みを残しますか? 一つにまとめますか?

次回予告

というわけで、買えなかった理由は分かりました。直した仕組みが、本当に効いているのか。それは、これから数日の記録で分かります。

次回は、前回の予告のとおり、買った銘柄の続きをお伝えします。持ち続けられたのか、売りの条件に当たったのか。そして、今回足した「二つの目」が、実際の判断に効いたかどうかも、あわせて報告します。
